# HoneyForge

Централизованная платформа для создания, развёртывания и мониторинга ловушек в лаборатории. Администратор собирает ловушку в конструкторе, а контроллер узла создаёт для неё изолированные контейнеры. Число ловушек ограничено политикой ёмкости узла, а не списком заранее описанных сервисов.

**Область применения:** только разрешённые изолированные лаборатории. Эмуляторы не запускают команды, не используют настоящие учётные записи и не обращаются к внешним сетям. Интерфейс на HTML, CSS и JavaScript не требует сборки; язык интерфейса — русский (`ru-RU`).

## Возможности

- **Конструктор ловушек** — мастер из семи шагов: сервис, сеть, ресурсы, мониторинг, проверка сервером, развёртывание.
- **Каталог сервисов** — восемь типов, включая TCP-баннер, HTTP-панель, HTTP-сайт, JSON API, два готовых сайта, Telnet-эмулятор и отдельный Linux sandbox. Доступность sandbox зависит от подготовленного отдельного узла.
- **Библиотека профилей** — многократно используемые шаблоны. Один профиль обслуживает любое число ловушек.
- **Конструктор страниц и маршрутов** для HTTP: страницы собираются из безопасных компонентов и хранятся как данные.
- **Динамическая среда выполнения** — на каждую ловушку контроллер создаёт контейнер приманки и контейнер агента с отдельным томом очереди, удостоверением и точкой подключения.
- **Автоматическое выделение портов**, проверка конфликтов и контроль ёмкости узла.
- **Жизненный цикл**: развёртывание, запуск, остановка, перезапуск, изменение настроек, применение новой версии профиля, дублирование, удаление с очисткой контейнеров.
- **Согласование состояния**: потерянные контейнеры восстанавливаются, осиротевшие удаляются, после перезапуска сервера состав ловушек сохраняется.
- **Телеметрия**: устойчивая очередь на стороне ловушки, передача по TLS, устранение дублей, PostgreSQL, обновление интерфейса по WebSocket.
- **Сетевая активность**: график событий ловушек по времени с периодами от 15 минут до 7 дней, фильтрами и обновлением без перезагрузки.
- **География угроз**: карта публичных источников с честной обработкой частных адресов; геолокация только по локальной базе, без передачи адресов наружу.
- **Понятные выводы**: подбор пароля, успешные входы, попытки загрузки программ — простым языком, со сравнением с предыдущим периодом.
- **История сеанса и карточка адреса**: все действия одного подключения по порядку и всё, что делал один адрес.
- **Отчёт для печати, экспорт адресов для блокировки, уведомления в Telegram** (необязательный отдельный сервис).
- **Готовые сайты**: интернет-магазин одежды и портал сотрудников, которые выглядят как настоящие и полностью редактируются в конструкторе.
- **Telnet-оболочка среднего уровня** записывает попытки входа и команды, ничего не выполняя. **Linux sandbox высокого уровня** подготовлен для реального Bash на отдельной VM с gVisor; запуск на таком узле ещё не проверен. Подробности и ограничения — в [инструкции sandbox](docs/sandbox.md).
- **Публикация ловушки во внешнюю сеть** по явному решению владельца узла и администратора; по умолчанию выключена.
- **Оповещения, аналитика, экспорт, журнал аудита, роли** администратора, оператора и наблюдателя.
- **Индустриальный тёмный интерфейс** с единой системой токенов, эффектом жидкого стекла и адаптивной раскладкой.

## Быстрый запуск

Нужны Docker с контейнерами Linux и Compose версии 2, а также Python 3.11 или новее.

```sh
python -m venv .venv
. .venv/bin/activate            # PowerShell: .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python infrastructure/scripts/setup.py
docker compose up --build -d --wait
```

`setup.py` создаёт исключённый из Git файл `.env` с секретами и локальный удостоверяющий центр. Существующие значения сохраняются; секреты на экран не выводятся. Добавьте в доверенные сертификаты браузера **только** `infrastructure/certs/ca.crt` и откройте **https://localhost:8443**. Имя и пароль администратора находятся в `.env`.

На Linux укажите в `.env` группу сокета Docker: `DOCKER_SOCKET_GID`, значение даёт команда `stat -c %g /var/run/docker.sock`. Подробности — в [инструкции по развёртыванию](docs/deployment.md).

При первом запуске создаются администратор, узел лаборатории и профили-шаблоны. Ловушки и события не подставляются.

## Создание ловушки

1. Войдите и откройте **Конструктор ловушек**.
2. Задайте название, выберите тип сервиса и профиль или создайте новый профиль.
3. Настройте сервис, узел и порт, ограничения ресурсов и мониторинг.
4. На шаге **Проверка конфигурации** сервер подтвердит, что порт свободен и ресурсов узла достаточно.
5. Нажмите **Создать и развернуть**. Откроется страница ловушки с фактическим ходом развёртывания; состояние «Работает» появится после подтверждения агента.
6. Подключитесь разрешённым тестовым клиентом по адресу из столбца «Точка подключения»:

   ```sh
   docker compose --profile demo run --rm test-client tcp hp-1a2b3c4d 8022
   docker compose --profile demo run --rm test-client http hp-5e6f7a8b 8080
   ```

7. События появятся в разделе **События в реальном времени** и на странице ловушки без перезагрузки.

Полное описание — в [руководстве пользователя](docs/user-guide.md).

## Автоматическая демонстрация

```sh
python infrastructure/scripts/demo.py
```

Скрипт запускает плоскость управления и через API создаёт три TCP- и три HTTP-ловушки по двум профилям. Затем он проверяет телеметрию каждого экземпляра, остановку и перезапуск одной ловушки, собственные настройки, применение новой версии профиля, клонирование, сбой канала управления с доставкой событий ровно один раз, удаление с очисткой контейнеров, восстановление удалённого контейнера, перезапуск сервера, ограничения ресурсов и изоляцию. В конце созданные экземпляры удаляются; ключ `--keep` оставляет их для показа. См. [сценарий показа](docs/demonstration.md).

## Проверка и тестирование

```sh
python -m pytest -q
```

Тесты используют временные базы SQLite и настоящие сокеты на `127.0.0.1`. Тесты одновременных операций выполняются только с PostgreSQL:

```sh
# Используйте одноразовую базу honeyforge_test*: тесты пересоздают таблицы.
export TEST_DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@localhost/honeyforge_test
python -m pytest -q
```

Проверки интерфейса требуют Node.js: `npm ci`, затем `npm run test:i18n` и `python infrastructure/scripts/audit_localization.py`. Браузерные сценарии `npm run test:ui` и `npm run test:ru-ui` дополнительно требуют Playwright и Chrome. GitHub Actions содержит задания с PostgreSQL и с полной демонстрацией Compose; наличие файла рабочего процесса не означает, что он успешно выполнен на GitHub.

Что именно проверено и что не запускалось, перечислено в [отчёте](docs/status.md).

## Режим разработки без Docker

```sh
python infrastructure/scripts/dev.py
```

Откройте http://127.0.0.1:8765. Это режим разработки интерфейса с SQLite. Контроллер в нём не запускается: ловушки можно сохранять как черновики, а развёртывание отклоняется с сообщением о недоступном контроллере.

## Структура проекта

```text
backend/app/         API, права доступа, модели, жизненный цикл, канал контроллера
backend/migrations/  история схемы Alembic
shared/              контракты конфигурации и событий, каталог сервисов, очередь SQLite
controller/          контроллер узла: согласование контейнеров через Docker Engine API
agent/               агент экземпляра: TLS, повторы, сообщения о состоянии
honeypots/           эмуляторы TCP и HTTP, вывод страниц, тестовый клиент
frontend/            интерфейс: конструктор, инвентарь, мониторинг
infrastructure/      образ, Compose, прокси, сертификаты, скрипты
tests/               тесты API, эмуляторов, контроллера, миграции и браузера
docs/                документация
```

## Ограничения

- Настраиваются только реализованные типы сервисов. Новый протокол добавляет разработчик как модуль эмулятора; исполняемый код из интерфейса не загружается.
- Ловушек высокого уровня взаимодействия, изолированных сред с настоящей оболочкой и дополнительных протоколов нет.
- Проверен один узел с локальным контроллером. Регистрация дополнительных узлов предусмотрена в API, но удалённые узлы не проверялись.
- Сервисы ловушек доступны только из сети ловушек лаборатории и не публикуются на интерфейсах узла.
- Порт ловушки уникален в пределах узла и сети; это политика адресации, а не техническое ограничение контейнеров.
- После пересборки образа работающие ловушки продолжают использовать прежний образ, пока их не создадут заново.
- Квота размера тома очереди не задаётся; объём ограничен числом событий в очереди.
- Один процесс сервера; уведомления WebSocket хранятся в памяти, источник данных — PostgreSQL.
- Шрифты Onest и Xolonium в репозиторий не входят; без них используется запасной стек. См. [дизайн интерфейса](docs/design.md).
- Геолокация источников выключена, пока оператор не разместит локальную базу диапазонов. В изолированной лаборатории источники имеют частные адреса и на карту не наносятся.
- Карта мира стилизованная, без границ государств; номер автономной системы не определяется.
- Нет honeytoken, экспорта STIX и внешних каналов уведомлений.
