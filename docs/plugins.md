# Добавление типа сервиса

Администратор создаёт любое число ловушек поддерживаемых типов и настраивает их данными. Новый сетевой протокол — это программный код, который добавляет разработчик. Загрузка исполняемого кода из интерфейса не предусмотрена намеренно.

## Что входит в модуль сервиса

| Часть | Где находится | Назначение |
|---|---|---|
| Запись реестра | `shared/catalog.py`, словарь `PLUGINS` | Ключ, название, описание, порт по умолчанию, типы событий, возможности, список настраиваемых полей, значения по умолчанию |
| Семейство и уровень | `shared/contracts.py`, словарь `SERVICE_FAMILIES` | Какой эмулятор обслуживает тип и какой у него уровень взаимодействия |
| Схема настроек | `shared/contracts.py`, класс `ProfileSpec` | Поля с ограничениями; проверяются сервером, агентом и приманкой |
| Эмулятор | `honeypots/service.py` | Обработка соединения и запись событий |
| Описание полей в интерфейсе | `frontend/specform.js`, таблицы `FIELDS` и `SECTIONS` | Вид редактора для каждого поля |
| Переводы | `frontend/locales/ru.json`, группы `fields` и `labels` | Русские подписи |

## Вариант существующего эмулятора

Новый вариант HTTP-сервиса не требует кода эмулятора. Достаточно:

1. Добавить ключ в `SERVICE_KEYS` и `SERVICE_FAMILIES`, а также в перечисление поля `service_key` класса `ProfileSpec`.
2. Добавить запись `ServicePlugin` в `PLUGINS` со страницами и маршрутами по умолчанию.
3. Добавить тест: значения по умолчанию должны проходить проверку схемы, а сервис — отвечать по заданным маршрутам.

Тип сразу появится в каталоге, конструкторе и библиотеке профилей.

## Новый протокол

1. Добавьте семейство эмулятора в `SERVICE_FAMILIES` и перечисление `service_type`. Значение семейства контроллер передаёт контейнеру приманки в переменной `SERVICE_TYPE`.
2. Опишите настройки протокола полями `ProfileSpec` с явными границами. Не добавляйте поля, значение которых интерпретируется как код, команда или выражение.
3. Реализуйте обработчик в классе `Decoy`. Обязательные свойства:
   - ограничение времени соединения и размера входных данных;
   - события создаются только методом `record`, который учитывает настройки записи и размер очереди;
   - никакого запуска процессов, чтения файлов по запросу клиента и исходящих соединений;
   - данные клиента сохраняются только в разрешённых полях события.
4. Если нужны новые поля события, добавьте их в список разрешённых в `EventInput.limited_payload` и решите, видны ли они наблюдателю (`event_view` в `backend/app/reporting.py`).
5. Добавьте новые типы событий в `EVENT_TYPES`, в перечисление поля `event_type` класса `EventInput` и переводы в группу `labels.event`.
6. Добавьте запись реестра, описание полей в `specform.js` и переводы.
7. Напишите тесты по образцу `tests/test_emulators.py`: настоящий сокет на `127.0.0.1`, проверка событий, границ и того, что секреты клиента не сохраняются.

Контроллер менять не нужно: он создаёт контейнер из того же образа с той же командой и передаёт только семейство эмулятора. Если протоколу нужен другой образ, его следует добавить в список разрешённых образов контроллера и в `Policy`; принимать имя образа из запроса API нельзя.

## Версия схемы

Поле `config_schema_version` записи реестра и `schema_version` конверта конфигурации агента равны 1. Добавление необязательного поля с значением по умолчанию совместимо: сервер при запуске дополняет сохранённые конфигурации экземпляров. Изменение смысла или удаление поля требует новой версии схемы и миграции сохранённых профилей.
