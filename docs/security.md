# Безопасность

HoneyForge предназначен для разрешённой изолированной лаборатории. Независимый аудит не проводился; соответствие требованиям промышленной эксплуатации не заявляется.

## Операторы

- Пароли хранятся как `scrypt` с солью. Сеанс — случайный токен в cookie с флагами `HttpOnly`, `Secure`, `SameSite=Strict`; в базе хранится только хеш токена. Сеансы истекают и отзываются при смене пароля или роли.
- Изменяющие запросы требуют заголовок `X-HoneyForge` и разрешённый `Origin`. WebSocket проверяет `Origin` и сеанс при подключении и перед каждой отправкой.
- Три роли: администратор, оператор, наблюдатель. Создание, клонирование, развёртывание и удаление ловушек, политика узлов и удостоверения агентов доступны только администратору. Наблюдатель не видит записанные имена пользователей и присланные клиентами данные.
- Число неудачных попыток входа ограничено на уровне учётной записи и прокси.

## Машинные удостоверения

| Удостоверение | Кто создаёт | Что может |
|---|---|---|
| Секрет контроллера | `setup.py`, хранится в `.env` | Получать требуемое состояние своего узла, регистрировать хеши секретов агентов, отчитываться о контейнерах |
| Секрет агента | Контроллер при развёртывании экземпляра | Получать конфигурацию и передавать события и состояние только своего экземпляра |

Сервер хранит только хеши `SHA-256`. Секрет агента существует в памяти контроллера в момент создания контейнера и в окружении контейнера агента; он не попадает в базу данных, журналы, ответы API и интерфейс. При потере контейнера агента контроллер создаёт новый секрет, и прежний перестаёт действовать. Администратор может отозвать доступ агента; смена секрета отзыв не отменяет. Удостоверение удаляется вместе с экземпляром.

Агент не может выдать себя за другой экземпляр: принадлежность событий определяется удостоверением, а пакет с чужим идентификатором ловушки отклоняется целиком. Секрет агента не подходит к каналу контроллера, и наоборот.

## Контроллер и доступ к Docker

Доступ к сокету Docker равнозначен правам администратора узла, поэтому он ограничен несколькими способами.

- Сокет смонтирован только в сервис `controller`. Сервер, прокси и контейнеры ловушек доступа к нему не имеют.
- У контроллера нет слушающих портов. Он сам обращается к серверу по TLS с проверкой сертификата и подключён только к сети управления.
- API не принимает имён образов, команд, монтирований, сетей и привилегий: запросы с такими полями отклоняются схемой. Требуемое состояние содержит только семейство эмулятора (`tcp` или `http`), псевдоним, порт и числовые ограничения.
- Перед созданием контейнера спецификация проходит проверку `Policy.assert_safe`: только образ `honeyforge:local`, только две сети лаборатории, только именованные тома с префиксом лаборатории, запуск не от `root`, корневая файловая система только для чтения, сброс всех возможностей ядра, запрет повышения привилегий, обязательные ограничения памяти, процессора и числа процессов. Привилегированный режим, монтирование путей узла, публикация портов, сети `host` и `bridge` отклоняются.
- Контроллер управляет только контейнерами и томами с метками своей лаборатории и своего узла и никогда не выбирает их по имени.
- Контейнер контроллера работает от непривилегированного пользователя с файловой системой только для чтения и без возможностей ядра.

Остаточный риск: уязвимость в самом контроллере дала бы доступ к Docker. Прокси для сокета с ограничением методов API не используется.

## Изоляция ловушек

- Приманка подключена только к внутренней сети `decoy`: у неё нет маршрута по умолчанию, имён DNS сервисов управления и исходящего доступа.
- Сервисы ловушек не публикуются на интерфейсах узла. Интерфейс управления опубликован только на `127.0.0.1`.
- Приманка не получает секретов, сертификатов и адреса управления. С агентом её связывает только общий том очереди.
- Эмуляторы не запускают команды, не читают файловую систему по запросу клиента и не обращаются к внешним системам. Данные клиента TCP только измеряются и сохраняются как ограниченный печатный фрагмент.
- Страницы HTTP выводятся доверенными шаблонами с экранированием; политика `Content-Security-Policy` запрещает сценарии. Пароли из форм не сохраняются.

Демонстрация проверяет изоляцию на работающих экземплярах: каждая приманка и тестовый клиент не могут подключиться к серверу, базе данных и прокси по IP, не видят их имён и не имеют исходящего маршрута.

## Готовые сайты и случайные посетители

Заготовки «магазин» и «портал» выглядят как настоящие сайты, поэтому на опубликованную ловушку может зайти обычный человек. Чтобы он ничего не потерял:

- Организации вымышлены: название берётся из настройки сервиса, адресов и телефонов нет.
- Единственная форма — вход. Имя пользователя записывается в событие, пароль отбрасывается сразу. Регистрации, оформления заказа и оплаты нет.
- Страницы не загружают ничего со стороны и не содержат сценариев: рисунки товаров ловушка рисует сама из фиксированного набора контуров и цветов, а ссылки ведут только на страницы того же сайта. Произвольные адреса, цвета и картинки конфигурация не принимает.
- Весь текст оператора экранируется, как и в остальных страницах.

Ответственность за содержимое опубликованного сайта несёт владелец узла: не используйте названия и оформление настоящих организаций.

## Telnet-эмулятор среднего уровня взаимодействия

Тип «Telnet-оболочка Linux» даёт посетителю диалог входа и командную строку вымышленного сервера. Это эмуляция, а не настоящая система:

- Ни одна введённая строка не выполняется. Ответы команд, содержимое файлов и список каталогов берутся из таблицы в `honeypots/shell.py`; модуль не запускает процессы, не открывает файлы и не устанавливает соединения.
- Программы загрузки и запуска (`wget`, `curl`, `tftp`, `busybox` и подобные) только записываются с повышенной критичностью и получают правдоподобный отказ. Ничего не загружается.
- Пароль читается, чтобы диалог выглядел настоящим, и сразу отбрасывается: в события попадают только имя пользователя и результат.
- Длина строки, число команд, объём принятых данных и время сеанса ограничены настройками профиля.
- Контейнер тот же, что у остальных ловушек: без привилегий, с файловой системой только для чтения и без секретов.

Этот тип имеет уровень medium: он не предоставляет реальную ОС или выполнение команд.

## Linux sandbox высокого уровня взаимодействия

Тип `linux-sandbox` подготовлен для реального выполнения Bash на отдельной VM/VPS. На узле центра его запуск запрещён. Рабочий контейнер запускается через gVisor (`runsc`), без сетевых интерфейсов, секретов и доступа к очереди агента; с непривилегированным пользователем, корневой файловой системой только для чтения и лимитами ресурсов. Ввод и вывод записывает отдельный шлюз.

Сброс выполняется пересозданием одноразового контейнера. Snapshot-revert всей VM не реализован. Сквозной запуск с настоящим gVisor на отдельной VM ещё не проверен; контрактные и модульные тесты не заменяют эту проверку. До успешной проверки готовности узла API не разрешает развёртывание. Ограничения записи, сбора файлов и датчиков описаны в [инструкции sandbox](sandbox.md).

## Уведомления в Telegram

Сервер приложения не имеет выхода в интернет, и это не меняется. Уведомления отправляет отдельный необязательный сервис `notifier`; по умолчанию он не запускается.

- Это единственный сервис с исходящим доступом. У него нет слушающего порта, доступа к Docker и к базе данных.
- Он обращается к серверу по каналу управления с собственным секретом (`NOTIFIER_TOKEN`) и может прочитать только новые оповещения и сбои ловушек. Без заданного секрета запрос закрыт для всех.
- В сообщении — название ловушки, название правила, счётчики и критичность. Адреса источников, имена пользователей и введённые посетителем данные через этот запрос не выдаются и в Telegram не попадают.
- Токен бота хранится в `.server.env` на сервере и в журнал не записывается.
- После перезапуска сервис сообщает только о новых событиях; неотправленное сообщение повторяется, уже отправленное — нет.

## Усиление сервера

Скрипт `infrastructure/server/harden-host.sh` владелец сервера запускает сам от root:

- Запрещает новые соединения из мостов Docker к самому серверу. Без этого контейнер ловушки мог подключиться к SSH узла через шлюз сети Docker; проверено изнутри контейнеров 13.10.2026. Ответы на соединения, открытые самим сервером, проходят. Правило восстанавливается при загрузке службой `honeyforge-host-guard`.
- Переводит SSH на вход только по ключу (`PasswordAuthentication no`, `PermitRootLogin prohibit-password`). Если в `/root/.ssh/authorized_keys` нет ключа, шаг пропускается, чтобы не потерять доступ; флаг `--no-ssh` пропускает его явно.

Эмулятор, кроме общего лимита соединений экземпляра, ограничивает одновременные соединения с одного адреса (не более восьми), чтобы один источник не занимал все слоты.

## Публикация ловушки во внешнюю сеть

По умолчанию ни одна ловушка не доступна за пределами лабораторной сети. Публикация включается в два шага, и оба выполняет человек.

1. Владелец узла перечисляет порты в окружении контроллера (`PUBLISH_PORTS`, по умолчанию пусто) и задаёт адрес привязки (`PUBLISH_ADDRESS`, по умолчанию `127.0.0.1`). Сервер управления не может расширить этот список: он лишь получает его в отчёте контроллера.
2. Администратор публикует конкретную ловушку на одном из этих портов. Оператор и наблюдатель этого сделать не могут; действие записывается в журнал аудита.

Что при этом гарантируется:

- Контроллер сам проверяет каждую спецификацию: ровно один порт TCP, только из списка узла, только на заданный адрес. Порты 22, 80, 443, 2375, 2376, 8443 и 9443 запрещены всегда.
- Опубликованный контейнер подключается к отдельной сети `exposed`. В ней выключены исходящая трансляция адресов и обмен между контейнерами: приманка отвечает на входящие подключения, но не может сама открыть соединение в интернет или к соседней ловушке. Если сеть настроена иначе, контроллер публикацию отключает.
- К сети управления опубликованный контейнер не подключается. Секретов, сертификатов и адреса сервера в приманке по-прежнему нет.
- Остальные ограничения контейнера сохраняются: файловая система только для чтения, без привилегий, с лимитами памяти, процессора и числа процессов.
- Интерфейс показывает ловушку опубликованной только после того, как контроллер увидел привязку порта в Docker.

Что остаётся на владельце узла: публикация означает приём враждебного трафика. Панель управления работает на том же узле, поэтому держите её пароль стойким, а вход в SSH — по ключу. Правила хостинг-провайдера и применимое право проверяет владелец узла. Скрипт `infrastructure/scripts/isolation.py` намеренно считает опубликованную ловушку нарушением изоляции.

## О скрытности канала управления

Исходное задание требует, чтобы взаимодействующий клиент не мог обнаружить и использовать инфраструктуру управления. Эта цель достигается защитной изоляцией, а не маскировкой трафика: канал управления находится в отдельной сети, недоступной из сети ловушек, зашифрован TLS, требует удостоверения и не имеет опубликованных адресов. Скрытые каналы, туннелирование, запутывание адресов и средства уклонения от мониторинга не реализованы намеренно.

## Данные

- В ловушках используются только вымышленные учётные записи. Разрешённые поля события перечислены в схеме; остальное отклоняется.
- События старше `RETENTION_DAYS` дней удаляются.
- Журнал аудита не содержит паролей, токенов и ключей.
- Файл `.env`, каталог `infrastructure/certs` и резервные копии базы данных содержат секреты и должны быть доступны только оператору лаборатории.

## Геолокация и приватность

- Адреса источников не передаются сторонним службам. Единственный источник геолокации — файл диапазонов, который оператор сам разместил на узле; по умолчанию геолокация выключена.
- Запрос географии возвращает только агрегаты по странам и точкам карты, без отдельных адресов.
- Частные, служебные адреса и адреса обратной петли никогда не получают местоположение, даже если указаны в файле.
- Интерфейс не загружает ресурсы с внешних адресов: шрифты, карта, значки и текстура фона отдаются сервером лаборатории, политика безопасности содержимого запрещает остальное.
- Сведения о событиях в канале WebSocket не содержат записанных имён пользователей и данных клиента; описание событий вставляется в страницу только как текст.

## Известные ограничения

- Один удостоверяющий центр лаборатории; сертификаты заменяются вручную.
- Роли действуют на всю лабораторию; отдельных разрешений на каждую ловушку нет.
- Секрет агента виден в окружении контейнера тому, кто имеет доступ к Docker узла.
- Квота размера тома очереди не задаётся; объём ограничен числом событий в очереди (`buffer_limit`).
- Один процесс сервера: уведомления WebSocket хранятся в памяти, источник данных — база.
