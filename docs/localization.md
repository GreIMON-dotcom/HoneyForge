# Русская локализация

Основной язык HoneyForge — `ru-RU`; HTML использует `lang="ru"` и UTF-8. Архитектура интерфейса без сборки сохранена. React и другие фреймворки не добавлялись. Acorn используется только проверкой исходного JavaScript в тестах и не загружается приложением.

## Инвентаризация

| Область | Источники текста | Способ перевода |
|---|---|---|
| Все девять страниц, вход, формы, окна, кнопки, уведомления | `frontend/app.js` | Семантические ключи общего словаря |
| Стартовая страница и справочник | `frontend/index.html`, `frontend/api-docs.html`, `frontend/api-docs.js` | Русский HTML и словарь |
| Статусы, роли, уровни, события, аудит, метаданные | Значения API, отображаемые `app.js` | Сопоставление `labels.*`; машинные значения не меняются |
| Числа, даты, относительное время, склонения | `frontend/i18n-core.js` | `Intl.NumberFormat`, `Intl.DateTimeFormat`, `Intl.RelativeTimeFormat`, `Intl.PluralRules` |
| Ошибки API и проверки данных | `backend/app/api.py`, `security.py`, `services.py`, `enrollment.py`, `reporting.py`, `main.py`, `localization.py`, `shared/contracts.py` | Русские сообщения; прежние HTTP-коды, поля и ограничения |
| OpenAPI | Сводки маршрутов и генератор в `localization.py` | Русские объяснения; идентификаторы схем и полей сохранены |
| Сообщения агента, ловушки и очереди | `agent/main.py`, `honeypots/service.py`, `shared/buffer.py` | Русские сообщения состояния и ошибок |
| Подготовка, эксплуатация и демонстрации | `infrastructure/scripts/*.py` | Русский вывод, справка и ошибки; UTF-8 в перенаправленном выводе |
| Документация | README и `docs/*.md` | Перевод инструкций, ограничений, таблиц и подписей диаграмм |

HoneyForge, API, HTTP, HTTPS, TCP, TLS, WebSocket, Docker, PostgreSQL, FastAPI, IP, JSON, CSV, SSH, SQL и UUID не переводятся.

## Устройство словаря

`frontend/locales/ru.json` — вложенный словарь с семантическими ключами. `t("profiles.name")` получает строку, `t("settings.editTitle", {name})` подставляет именованный параметр. `plural("counts.events", n)` выбирает one/few/many/other по русским правилам, включая 0, 11, 21 и дробные значения. `label(category, value)` переводит известные перечисления без изменения API.

Отсутствующий ключ даёт «Текст недоступен», неизвестное значение перечисления — «Неизвестно», отсутствующий параметр — тире. В обычном режиме ключи и диагностика не раскрываются. Для разработки можно до загрузки модуля задать `data-i18n-debug="true"` на HTML: отсутствующие ключи будут записываться в консоль. Тесты отдельно запрещают неразрешённые ключи.

Переводчик возвращает текст, не доверенный HTML. Интерполяция пользовательских значений перед вставкой в HTML проходит `esc`, а текстовые узлы используют textContent. Проверка браузера сохраняет строку с `<img …>` и убеждается, что она остаётся текстом после повторной загрузки.

Даты отображаются в 24-часовом формате `ru-RU` в часовом поясе браузера; UTC в БД и преобразование фильтров в ISO не меняются. Относительное время доступно в подсказке последней связи. Числа используют русскую десятичную запятую и неразрывный пробел. IP, порты, UUID и исходные числовые поля JSON не форматируются как обычные счётчики.

## Намеренно непереводимые данные

- Пользовательские названия, описания, имена учётных записей и сохранённая телеметрия отображаются как введены или записаны. Локализация не переписывает существующую БД. Старые `Lab low`, `Lab medium`, `Demo low`, `Demo medium` и прежние тестовые правила могут оставаться в лаборатории; новые стандартные профили получают русские названия.
- Исходные JSON в раскрываемых разделах и предпросмотре содержат реальные ключи API. Отдельная русская подпись объясняет этот режим.
- UUID, адреса, API-пути, значения протокола, технические поля CSV/IOC, SQL, команды и имена переменных окружения сохранены для совместимости.
- Субъекты сертификатов `HoneyForge Local Lab CA` и `HoneyForge laboratory` сохранены для идентификации существующей инфраструктуры.
- Внешние Docker, PostgreSQL, Alembic, pytest, HTTP-клиент и системные средства могут выводить собственную диагностику по-английски. Она не подменяется вымышленным переводом. Человекочитаемые сообщения самих скриптов HoneyForge переведены.

Точный перечень оставшихся строк исходников с путями, строками и причинами формирует `artifacts/localization-audit.json`. Браузерная проверка создаёт `artifacts/ru-ui/report.json` с фактическими сохранёнными данными, исключениями и найденными непереведёнными строками. Эти отчёты не подменяют визуальный осмотр.

## Повторяемые проверки

```sh
python -m pytest -q
npm ci --ignore-scripts
npm run test:i18n
python infrastructure/scripts/audit_localization.py
node --check frontend/app.js
```

При нестандартном расположении Node передайте `--node /path/to/node` скрипту аудита. Для PostgreSQL используйте `TEST_DATABASE_URL` либо `check_postgres.py`, как описано в README.

В работающей лаборатории с проверяемым TLS выполните `npm run test:ru-ui`; он проверяет русский вход и ошибку пароля, все девять разделов при ширине 1440/768/390, форму, сохранение кириллицы после обновления, экранирование и справочник. Снимки и отчёт сохраняются в `artifacts/ru-ui/`. Среда браузера намеренно имеет английскую локаль: приложение всё равно форматирует данные по-русски. `test:ui` проверяет живые события, а `test:deployment` — одобрение и создание дополнительного контейнера.

Состояние выполненных проверок и ограничения доказательств приведены в [отчёте локализации](localization-verification.md). [Снимок аудита](localization-audit.json) включён в поставку; повторный запуск создаёт актуальный отчёт в `artifacts/`.
