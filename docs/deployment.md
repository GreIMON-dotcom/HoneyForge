# Развёртывание и эксплуатация

## Требования

- Docker Engine или Docker Desktop с контейнерами Linux и Compose версии 2.
- Python 3.11 или новее на узле — для подготовки секретов и запуска демонстрации. На Ubuntu/Debian может потребоваться пакет `python3-venv`.
- Свободный порт 8443 на адресе 127.0.0.1.

## Первый запуск

Команды выполняются из корня полученного репозитория, где лежит `compose.yaml`. Для Linux:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python infrastructure/scripts/setup.py
printf '\nDOCKER_SOCKET_GID=%s\n' "$(stat -c %g /var/run/docker.sock)" >> .env
docker compose build backend
docker compose up --no-build -d --wait
```

Команды для Windows PowerShell приведены в [быстром запуске](../README.md#быстрый-запуск). Общий образ собирается через `backend` один раз, чтобы несколько сервисов не пытались одновременно записать один тег.

`setup.py` создаёт `.env` с секретами базы данных, администратора и контроллера узла, а также локальный удостоверяющий центр и сертификат сервера. Существующие значения не заменяются; секреты не выводятся на экран. Добавьте `infrastructure/certs/ca.crt` в доверенные сертификаты браузера лаборатории и откройте https://localhost:8443. Имя и пароль администратора находятся в `.env`.

При первом запуске сервер создаёт администратора, узел `lab-docker` и профили-шаблоны. Ловушки и события не создаются.

## Сервисы Compose

| Сервис | Назначение | Сети |
|---|---|---|
| `postgres` | База данных | `database` |
| `migrate` | Применение миграций перед запуском сервера | `database` |
| `backend` | API, интерфейс, WebSocket | `database`, `control` |
| `nginx` | TLS: порт 8443 для операторов, 9443 для агентов и контроллера | `ingress`, `control`, `management` |
| `controller` | Создание и согласование контейнеров ловушек | `management` |
| `decoy-network` | Одноразовый сервис: гарантирует, что Compose создал сеть ловушек до первого экземпляра | `decoy` |
| `test-client` | Разрешённый тестовый клиент, запускается вручную с профилем `demo` | `decoy` |

Контейнеры ловушек в `compose.yaml` не описаны. Их создаёт контроллер с именами вида `hf-<проект>-<идентификатор>-decoy` и `-agent` и томом `hf-<проект>-<идентификатор ловушки>`. Принадлежность определяется метками `io.honeyforge.managed`, `project`, `host`, `honeypot`, `role`, `deployment`, `profile`.

## Требования контроллера

Контроллеру нужен сокет Docker узла. В `compose.yaml` он смонтирован только в сервис `controller`. Контейнер работает от пользователя 10001 и получает доступ к сокету через дополнительную группу `DOCKER_SOCKET_GID`.

| Узел | Значение `DOCKER_SOCKET_GID` |
|---|---|
| Docker Desktop (Windows, macOS) | `0` — значение по умолчанию |
| Linux | Группа сокета: `stat -c %g /var/run/docker.sock` |

Перед первым циклом контроллер проверяет, что сети ловушек и управления внутренние и что образ `honeyforge:local` существует. При несоответствии он ничего не создаёт и сообщает об ошибке в журнале.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `POSTGRES_PASSWORD`, `ADMIN_USERNAME`, `ADMIN_PASSWORD` | Секреты базы данных и первого администратора | создаёт `setup.py` |
| `CONTROLLER_TOKEN` | Секрет контроллера узла `lab-docker`; сервер хранит только хеш | создаёт `setup.py` |
| `ALLOWED_ORIGIN`, `MANAGEMENT_PORT` | Адрес интерфейса и публикуемый порт | `https://localhost:8443`, `8443` |
| `HEARTBEAT_TIMEOUT` | Через сколько секунд без сообщений агент и контроллер считаются недоступными | `45` |
| `OPERATION_TIMEOUT` | Через сколько секунд неподтверждённая операция считается ошибкой | `180` |
| `RETENTION_DAYS` | Срок хранения событий и журнала развёртываний | `30` |
| `GEOIP_PROVIDER`, `GEOIP_FILE` | Необязательная локальная геолокация: `csv` и имя файла в `infrastructure/geoip` | `none`, `ranges.csv` |
| `PUBLISH_PORTS`, `PUBLISH_ADDRESS` | Порты узла, которые администратор может опубликовать для ловушек (`23,2222,8080-8089`), и адрес привязки. См. [безопасность](security.md) | пусто, `127.0.0.1` |
| `ORPHAN_POLICY` | `remove` — удалять управляемые контейнеры без записи в базе; `report` — не трогать | `remove` |
| `DOCKER_SOCKET_GID` | Группа сокета Docker внутри контейнера | `0` |

Секреты агентов в `.env` не хранятся: контроллер создаёт их при развёртывании каждого экземпляра.

## Шрифты и геолокация

Шрифты Onest и Xolonium подключаются размещением файлов в `frontend/fonts` и пересборкой образа; правила именования — в [описании дизайна](design.md). Геолокация публичных источников включается размещением файла диапазонов в `infrastructure/geoip`; формат и ограничения — в [описании аналитики](analytics.md). Оба шага необязательны.

## Публикация ловушек во внешнюю сеть

Нужна, только если ловушки должны принимать подключения извне. На сервере выполните в каталоге проекта:

```text
sh infrastructure/server/enable-publication.sh 23,2222,2323,8080-8089,8888
sh infrastructure/server/up.sh
```

Первый скрипт записывает в `.server.env` параметры `PUBLISH_PORTS` и `PUBLISH_ADDRESS=0.0.0.0`, второй пересобирает и перезапускает сервисы. Compose создаст сеть `exposed`, контроллер сообщит список портов серверу. После этого на странице ловушки у администратора появится действие «Опубликовать порт». Порты должны быть открыты в межсетевом экране узла и у провайдера. Чтобы выключить публикацию, сначала снимите её с ловушек, затем очистите `PUBLISH_PORTS`.

## База геолокации на сервере

```text
sh infrastructure/server/fetch-geoip.sh
sh infrastructure/server/up.sh
```

Первый скрипт загружает с `download.db-ip.com` файл «IP to Country Lite» за текущий месяц (около 5 МБ, лицензия CC BY 4.0), распаковывает его в `infrastructure/geoip/ranges.csv` и записывает в `.server.env` параметры геолокации и подпись источника, которую требует лицензия. Загружается только файл базы; адреса источников событий никуда не передаются. Обновление — повторный запуск раз в месяц.

## Уведомления в Telegram

```text
sh infrastructure/server/enable-telegram.sh
sh infrastructure/server/up.sh
```

Первый скрипт спрашивает токен бота (его выдаёт @BotFather) и числовой идентификатор чата и записывает их в `.server.env`; второй запускает сервис уведомлений вместе с остальными. Перед этим напишите боту любое сообщение, иначе он не сможет написать вам первым. Выключение: `sh infrastructure/server/enable-telegram.sh off` и повторный запуск. Что именно передаётся — в [безопасности](security.md).

## Усиление сервера

```text
sh infrastructure/server/harden-host.sh
```

Запрещает контейнерам открывать соединения к самому серверу и переводит SSH на вход только по ключу (подробности — в [безопасности](security.md)). Перед запуском убедитесь, что входите по ключу; запасной вход — консоль в панели хостинга.

## Политика узла

Ограничения по умолчанию: 12 ловушек, 8 ядер, 4096 МБ памяти, порты 8000–8999. Администратор меняет их в разделе «Ресурсы лаборатории» или запросом `PATCH /api/v1/hosts/lab-docker`. Каждая развёрнутая ловушка занимает свои ограничения и дополнительно 96 МБ и 0,25 ядра на агента.

## Обновление

```sh
python infrastructure/scripts/setup.py
docker compose up --build -d --wait --remove-orphans
docker compose restart nginx
```

Перезапуск `nginx` нужен, если изменился файл `infrastructure/nginx/nginx.conf`: он смонтирован в контейнер, и Compose не пересоздаёт сервис при изменении содержимого файла. После пересборки образа уже работающие контейнеры ловушек продолжают использовать прежний образ, пока экземпляр не будет удалён и создан заново.

Переход с версии двух слотов описан в [инструкции по миграции](migration.md).

## Резервная копия и восстановление

```sh
docker compose exec -T postgres pg_dump -U honeyforge honeyforge > backup.sql
```

`docker compose down` сохраняет том базы данных. `down -v` удаляет все данные лаборатории. Контейнеры и тома ловушек не принадлежат Compose и командой `down` не удаляются. Чтобы убрать их, удалите ловушки в интерфейсе при работающем контроллере. Если плоскость управления уже остановлена:

```sh
docker ps -aq --filter label=io.honeyforge.managed=true | xargs -r docker rm -f
docker volume ls -q --filter label=io.honeyforge.managed=true | xargs -r docker volume rm
```

## Устранение неполадок

| Признак | Что проверить |
|---|---|
| Создание отклонено: «Контроллер узла недоступен» | `docker compose ps controller` и `docker compose logs controller`. Контроллер должен быть в состоянии `healthy` |
| В журнале контроллера код 403 при обращении к `/runtime/` | `nginx` работает со старой конфигурацией: `docker compose restart nginx` |
| В журнале контроллера ошибка доступа к сокету | Неверное значение `DOCKER_SOCKET_GID` |
| Ловушка в состоянии «Ошибка»: «Образ сервиса не найден» | Соберите образ: `docker compose build`, затем «Развернуть» на странице ловушки |
| «Недостаточно оперативной памяти» или «достигнут предел числа ловушек» | Удалите ненужные экземпляры или увеличьте политику узла в разделе «Ресурсы лаборатории» |
| «Конфликт портов» | Порт занят другой ловушкой. Выберите автоматическое выделение или свободный порт; занятые порты показаны в разделе «Ресурсы лаборатории» |
| Ловушка долго в состоянии «Развёртывание» или «Запускается» | Журнал операций на странице ловушки; затем `docker logs` контейнеров приманки и агента. Через `OPERATION_TIMEOUT` состояние сменится на «Ошибка» |
| Агент «Нет соединения» | Контейнер агента запущен? Доступ не отозван в разделе «Мониторинг развёртывания»? Работает ли `nginx`? |
| Нет событий | Включена ли телеметрия и нужные виды записи в настройках экземпляра; размер очереди на странице ловушки; фильтры в разделе событий |
| Ловушка «Удаляется» и не исчезает | Контроллер недоступен. Восстановите его или используйте «Удалить без ожидания контроллера» |
| После перезапуска сервера ловушки «Не в сети» | Состояние восстановится после следующих сообщений агентов, обычно в течение десяти секунд |
| Контейнеры пересоздаются | Запись ловушки существует, а контейнер удалён вручную — это штатное восстановление. Смотрите `runtime.recovered` в журнале аудита |
| Ошибка TLS в браузере | Добавьте `infrastructure/certs/ca.crt` в доверенные, используйте имя `localhost`, проверьте срок действия сертификата |
