### Ошибки, найденные при проверке и исправленные

- На PostgreSQL события второй половины каждого интервала попадали в следующий интервал, а самые свежие выпадали из графика: приведение дробного числа к целому в PostgreSQL округляет. Номер интервала теперь вычисляется целочисленным делением; добавлен тест. На SQLite ошибка не проявлялась, её показал снимок рабочего стенда.
- Блок «Состояние системы» показывал «Нет соединения» для канала живых обновлений, пока шапка показывала активное соединение: блок рисовался до открытия канала. Теперь он обновляется при открытии.
- Групповые адреса определялись как публичные; порядок проверок в классификации исправлен.
- На узком экране пояснение пустой карты перекрывало карту и легенду; теперь оно выводится под картой.
- В словаре оставались три строки без кириллицы; исправлено по результату аудита.

### Что не проверялось и чего нет

- Сценарии Playwright `tests/ui-smoke.cjs` и `tests/ui-localization.cjs` обновлены под новый интерфейс, но не запускались: на узле нет Node.js и Playwright.
- Автоматическая проверка контраста и проверка программой чтения с экрана не выполнялись. Контраст мелкого текста пересчитан вручную для основных сочетаний.
- Снимок на ширине 1440 пикселей проверялся глазами, без скрипта переполнения; остальные ширины — скриптом и глазами.
- Геолокация с настоящей базой диапазонов и настоящими публичными источниками на рабочем стенде не проверялась: таких источников в изолированной лаборатории нет.
- Вид интерфейса со шрифтами Onest и Xolonium не проверялся, поскольку файлы не установлены.
- Карта не содержит границ государств; номер автономной системы не определяется; линии между источниками и ловушками не рисуются.
- Сравнение показателей с предыдущим периодом не выводится: сервер не хранит таких агрегатов.
- Произвольный диапазон дат для сетевой активности не реализован: доступны пять фиксированных периодов.

Ограничения и непроверенное:

- Оболочка — эмуляция с фиксированной таблицей ответов; внимательный человек отличит её от настоящей системы. Поддерживается только Telnet, не SSH.
- Форма настроек оболочки в мастере и отображение её событий в интерфейсе глазами не проверялись.
- Из опубликованной приманки доступен SSH самого узла через шлюз сети Docker; эмулятор соединений не открывает, но закрыть это правилом межсетевого экрана стоит.
- Скрипт `infrastructure/server/fetch-geoip.sh` на сервере не запускался до передачи владельцу; тесты PostgreSQL, `demo.py` и аудит локализации после версий 2.2–2.3 не запускались.

### Реализовано частично или с оговорками

- **Таблица типов сервисов.** Типы хранятся в реестре кода, а не в таблице БД: добавить тип может только разработчик вместе с эмулятором.
- **Публикация портов на узле.** Поле `published_port` есть, публикация не выполняется намеренно: ловушки доступны только из сети лаборатории.
- **Ограничение хранилища.** Квота размера тома не задаётся; объём очереди ограничен числом событий.
- **Ограничение числа сеансов HTTP.** Задаётся число одновременных соединений; число имитируемых сеансов ограничено постоянной величиной 1024 на экземпляр.
- **Загрузка процессора и памяти узла.** Показываются число процессоров, объём памяти узла и потребление каждой ловушки по данным Docker; суммарная загрузка узла в процентах не измеряется.
- **Состояния `pending` и `validating`.** Проверка выполняется синхронно в запросе, поэтому эти состояния не сохраняются; у них есть русские подписи.
- **Несколько узлов.** API регистрации узлов есть и проверено тестом прав доступа; работа второго контроллера на другом узле не проверялась.
- **Обновление образа.** Работающие ловушки не пересоздаются при пересборке образа.

### Не реализовано

Ловушки высокого уровня взаимодействия, дополнительные протоколы, honeytoken, экспорт STIX, геолокация, внешние каналы уведомлений, автоматическая замена сертификатов, отдельные разрешения на каждую ловушку, несколько процессов сервера.

## Ошибки, найденные проверками и исправленные

- На чистой установке Compose не создавал сеть ловушек, потому что ни один постоянный сервис её не использует, и контроллер отказывался работать. Добавлен одноразовый сервис `decoy-network`.
- Интерфейс сохранял неизменённые страницы и маршруты как собственные настройки экземпляра: сравнение зависело от порядка ключей, который PostgreSQL меняет. Сервер теперь отбрасывает значения, равные профилю; добавлен тест.
- `setup.py` после правки содержал синтаксическую ошибку; найдена тестом, исправлена.
- Сквозной тест предполагал близкие номера свободных портов; на Linux это неверно, тест исправлен.
- После обновления `nginx` работал со старой конфигурацией и отклонял канал контроллера; шаг перезапуска добавлен в инструкции.

## Что не проверялось

- Браузерные сценарии `tests/ui-smoke.cjs` и `tests/ui-localization.cjs` переписаны под новый интерфейс, но **не запускались**: на узле нет Node.js и Playwright. Их синтаксис проверен, поведение интерфейса проверено вручную.
- Рабочий процесс GitHub Actions изменён, но на GitHub не выполнялся.
- Работа на Linux с группой сокета Docker, отличной от 0, не проверялась; параметр `DOCKER_SOCKET_GID` описан в документации.
- Второй узел с собственным контроллером и удалённые узлы.
- Дополнение `compose.server.yaml` для сервера с доменным именем проверено 13.10.2026 на одном сервере (Ubuntu 26.04, Docker 29.1.3): сертификат Let's Encrypt, вход, создание ловушки контроллером, доставка события, удаление. При этом исправлен образ прокси: со сброшенными привилегиями Caddy не запускался из-за файловой привилегии бинарника. Сценарий `tests/server_smoke.py` по-прежнему написан под старые два слота и не запускался; живые обновления по WebSocket через внешний адрес не проверялись.
- Сертификаты лабораторного центра из `setup.py` не содержат расширения Authority Key Identifier: клиенты на Python 3.13 и новее со строгой проверкой их отклоняют. Контейнеры проекта используют Python 3.11 и работают.
- Отчёты `localization-verification.md` и `localization-audit.json` относятся к версии 1.0.
- Результаты версии 2.0 в таблицах ниже получены до редизайна; актуальные числа тестов приведены в разделе о версии 2.1.
