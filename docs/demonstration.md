# Сценарий показа

Показ использует настоящие работающие компоненты. События создаёт трафик тестового клиента лаборатории; в базу данных ничего не подставляется.

## Подготовка

```sh
python infrastructure/scripts/setup.py
docker compose up --build -d --wait
```

Откройте https://localhost:8443 и войдите как администратор. Проверьте в разделе «Панель управления», что в блоке «Состояние системы» контроллер узла на связи.

## Автоматический показ

```sh
python infrastructure/scripts/demo.py --keep
```

Ключ `--keep` оставляет созданные ловушки работать, чтобы показать их в интерфейсе. Без ключа скрипт удаляет всё созданное. Каждый шаг завершается проверкой; при несоответствии скрипт останавливается с ошибкой.

| Шаг | Что делает скрипт | Что проверяется |
|---|---|---|
| 1–3 | Запускает плоскость управления, входит как администратор, показывает состав ловушек и каталог | TLS с проверкой сертификата, контроллер на связи, на узле есть место |
| 4 | Создаёт профиль TCP и профиль HTTP | Профили сохранены |
| 5–6 | Разворачивает три ловушки по каждому профилю | Шесть разных идентификаторов, агентов, портов и пар контейнеров; все в состоянии «Работает» |
| 7 | Тестовый клиент подключается к каждой ловушке | События всех шести в PostgreSQL, у каждого события порт своей ловушки, сообщения WebSocket для всех шести |
| 8 | Фильтрует события по ловушке и типу | Ровно одна попытка аутентификации у выбранной HTTP-ловушки |
| 9 | Останавливает одну ловушку | Её порт закрыт, остальные пять отвечают клиенту |
| 10 | Перезапускает её и меняет собственный баннер | Новый баннер у этой ловушки, прежний у соседней |
| 11 | Меняет профиль | Ловушки не изменились; после «Применить обновления» новая версия только у выбранной |
| 12 | Клонирует HTTP-ловушку | У клона свои идентификатор, порт, агент и пустая история; события исходной не изменились |
| 13 | Отключает агента от сети управления и подключается к ловушке | Событие осталось в очереди и не попало в базу; после восстановления доставлено ровно один раз |
| 14 | Останавливает и удаляет две ловушки | Контейнеры и тома удалены, порты освобождены, записи исчезли |
| 15 | Удаляет контейнер приманки командой Docker | Контроллер создал контейнер заново, ловушка отвечает клиенту |
| 16 | Перезапускает сервер управления | Ловушки на месте, контейнеры те же, события сохранены |
| 17 | Сверяет ограничения контейнеров с конфигурацией | Память и процессор контейнеров равны настройкам экземпляров |
| 18 | Проверяет изоляцию | Приманки и тестовый клиент не достигают сервера, базы и прокси; нет имён DNS управления, маршрута наружу, секретов в окружении приманки |
| 19–20 | Показывает журнал аудита и удаляет созданное (без `--keep`) | В аудите есть регистрация, развёртывание, клонирование, удаление, создание удостоверения, восстановление |

## Показ в интерфейсе

1. **Каталог сервисов** — четыре реализованных типа сервисов.
2. **Библиотека профилей** — профили демонстрации и число ловушек у каждого.
3. **Конструктор ловушек** — создайте ловушку «HTTP-сайт»: на шаге «Настройка сервиса» добавьте компонент в конструкторе страниц, на шаге «Сетевые настройки» нажмите «Проверить точку подключения», на шаге «Мониторинг» включите правило оповещения с порогом 1, затем «Создать и развернуть».
4. **Страница ловушки** — журнал операций показывает создание тома и контейнеров, регистрацию агента и подтверждение; состояние меняется на «Работает» без перезагрузки.
5. Подключитесь тестовым клиентом по показанному адресу:

   ```sh
   docker compose --profile demo run --rm test-client http hp-XXXXXXXX 8081
   ```

   На странице появятся события и уведомление о сработавшем правиле.
6. **Все ловушки** — несколько экземпляров одного профиля с разными портами; поиск, фильтр по типу и состоянию.
7. **События в реальном времени** — фильтр по ловушке и типу события, сведения о событии.
8. **Настройки экземпляра** — измените описание сайта; состояние «Обновляется» сменится на «Работает», соседние ловушки не изменятся.
9. **Дублировать ловушку**, затем остановка и **Удалить экземпляр** — запись исчезает после удаления контейнеров.
10. **Ресурсы лаборатории** — бюджет узла, потребление памяти каждой ловушкой, выделенные порты.
11. **Мониторинг развёртывания** — история развёртываний с журналом шагов и удостоверения агентов.
12. **Журнал аудита** — все выполненные операции.

## Показ согласования вручную

```sh
docker ps --filter label=io.honeyforge.role=decoy
docker rm -f <контейнер приманки>
```

Через несколько секунд контейнер появится снова, а в журнале аудита — запись «Восстановление контейнеров ловушки».

## Завершение

Удалите ловушки демонстрации в интерфейсе: остановите каждую и нажмите «Удалить экземпляр». `docker compose down` останавливает плоскость управления и сохраняет данные.
